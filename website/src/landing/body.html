staying afloat in an ocean of slop

ship is a small terminal workspace that gives you and your coding agents somewhere steady to work while everyone else keeps shipping more slop.

run your editor, shells and agents side by side, see who needs you, and close the window without stopping the work.

$ git clone https://github.com/shipmux/ship.git
$ cd ship
$ cargo install --path crates/ship

a work in progress you can try today. builds from source with rust and zig 0.17.

deck what works today

keep a project together while several things are happening at once. these all work today, with successful use on linux and macos. windows is best effort.

it keeps running

  • leave and come back

    close the window or press alt-q, and your programs keep running on the background server. run ship again to carry on.

  • get your layout back

    after a server restart or reboot, your tabs, splits, stacks and directories return with fresh shells. the layout comes back, not the old running programs.

  • several windows, same work

    open ship from more than one terminal. each window chooses what to look at, while the tabs, panes and running programs are shared.

it keeps you in the loop

  • know who needs you

    see who's working, waiting for an answer or finished unseen. a sound lets you know when something needs attention, and alt-a takes you there.

  • a tab for the whole project

    keep the api, docs and review under one project tab. fold the parts you aren't looking at, and move or rename tabs with the keyboard or mouse.

  • split panes and stacks

    split when you want things side by side, or press alt-s for a shell on top without making your panes smaller. the pane behind it keeps running.

  • search in your own editor

    press alt-e to open scrollback in your editor and search with familiar keys. or drag to copy straight from a pane.

it's yours to script

  • a cli for scripts and agents

    open panes, send text or keys and read output with ship commands. use explicit pane ids so changing your selection doesn't redirect a script.

  • hand work to another agent

    an agent can open a second pane, give another agent a task, wait for its status report and read the reply. no sdk or plugin needed.

  • keep your habits

    change keys and menus, add a tmux-style prefix, or run your own scripts from a key. save the config and open windows pick up the changes.

not built yet

  • releases and packages.
  • built-in history search and keyboard copy mode. use your editor instead.
  • resuming agent conversations or rerunning programs after a server restart. saved tabs start fresh shells.
  • a combined view of servers on several machines. you can already run ship over ssh or forward a remote socket.

waterline the ocean of slop why ship

this is the water everyone else keeps shipping into: readmes that promise everything, pull requests nobody read to the end, and features that exist because generating them was cheaper than deciding not to.

ship can't review your work for you. it gives you somewhere to stay involved, with your editor beside the agents, a sidebar that tells you who needs an answer, and room to check what came back before you send it out.

below deck how it works

your programs live on a background server. the terminal window is how you look at them, and the cli lets scripts and agents join in.

a server that stays up

the first ship starts a server for you. detach, close the terminal or open another window, and the same programs are still there. each window can look at a different part of the work.

the local connection is restricted to your user account. to work on another machine, use ssh. stopping the server is different from closing a window: ship server stop ends every program inside it.

tabs and panes

keep an editor beside a test run, nest smaller tasks under a project tab, or stack a spare shell over a busy pane. new splits and stacked shells open in the directory you were working in. zoom in when you need more room, then return to the same layout.

claude code, codex, pi and crush report their own state through the program status protocol. ship shows it in the sidebar and on their tabs, so an agent waiting for permission stays visible even when its tab is folded.

use the terminal to drive it

create a pane, run a command, read its output and close it, all from a shell script. commands that return tabs or panes print json, pane read prints text, and commands with no result stay quiet on success.

try this with ship and jq installed. a demo tab appears, a command counts to 100, and the last three lines come back to your terminal.

agents driving agents

an agent can open a second agent in a pane, send it a task and read back the answer, using the same commands you would type yourself.

waiting uses the program's status reports, not a guess at what's on screen. a reply might mean finished, blocked on a question or an error, so the caller can decide what to do next. the handoff guide covers the full loop and what to do if a wait fails.

install

ship builds from source for now. install the build prerequisites, including rust, zig 0.17 and git, then:

$ git clone https://github.com/shipmux/ship.git
$ cd ship
$ cargo install --path crates/ship

run ship to open a shell. try alt-| to split it, then alt-q to detach. run ship again and both shells are still there.

on macos, set your terminal to use option as alt, often called "option as meta", or ship's keys will type special characters instead.

keys

in normal mode, ship uses alt chords and other keys go to the selected pane. start with these, and keep the full key list nearby.

a selection of default keys
alt-nnew tab with a shell
alt-xclose the tab
alt-| alt--split the pane right or down
alt-sstack a shell in front of the pane
alt-, alt-.previous or next pane in the stack
alt-eopen scrollback in your editor
alt-h alt-j alt-k alt-lmove to the pane left, below, above or right
alt-tabnext pane in the tab
alt-ajump to the next agent that needs you
alt-ppanes mode to move, swap or rename; esc leaves
alt-fzoom the pane to fill the tab, or unzoom
alt-rresize mode: h j k l move the pane's edge, esc leaves
alt-ttabs mode to navigate, fold, move or rename; esc leaves
alt-bhide or show the sidebar
alt-pageup alt-pagedownscroll the pane up or down a page
alt-qdetach

the mouse works too, a little further down.

config

ship reads ~/.config/ship/config.toml, or $XDG_CONFIG_HOME/ship/config.toml. without one it uses its defaults, and a running window picks up changes as soon as you save.

[server.defaults.pane]
exit_behavior = "keep_failed"  # keep failed commands open

[client]
sidebar_width = 34

[client.modes.normal.keys]
"ctrl-b" = { action = { client.mode = "prefix" } }
# tmux habits

[client.modes.prefix]
kind = "oneshot"   # back to normal after one key

[client.modes.prefix.keys]
"c"      = { action = { server.tab.create = { starter = "shell", select = true } } }
"ctrl-b" = { action = { client.send = "ctrl-b" } }

copy only what you want to change. this example keeps failed commands open, makes the sidebar wider and adds a tmux-style prefix. ship config check lists any mistakes before you try it.
